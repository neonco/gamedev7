## Что такое класс и что такое объект?

- [ ] это одно и то же, просто разными словами
- [x] класс — чертёж, объект — изделие по чертежу
- [ ] класс — для больших программ, объект — для маленьких

> Из одного класса `Snake` мы сделали двух змеек. Чертёж один, изделия разные, и у каждого свои данные.

## Зачем внутри методов пишут `self`?

- [ ] так требует pygame
- [x] чтобы отличать данные этой змейки от чужих
- [ ] чтобы метод работал быстрее

> `self.body` означает «тело вот этой змейки». Без `self` было бы непонятно, чьё это тело.

## Когда выполняется `__init__`?

- [ ] каждый раз, когда змейка делает шаг
- [x] один раз, когда объект создаётся
- [ ] только если его вызвать вручную

> `__init__` заполняет начальное состояние: где змейка стоит, куда смотрит, какие клавиши слушает.

## Что произойдёт, если написать `len(player1)`?

- [ ] ошибка: у объектов нельзя брать длину
- [x] вызовется метод `__len__`, и мы получим длину тела
- [ ] вернётся количество съеденной еды

> Python сам вызывает `__len__`, когда видит `len()`. Это и есть перегрузка оператора: снаружи обычная операция, внутри — наш код.

## Почему клавиши передаются в змейку снаружи, а не записаны внутри класса?

- [ ] так короче код
- [x] чтобы один класс годился для обоих игроков
- [ ] иначе pygame не увидит нажатия

> Если записать WASD внутри класса, вторая змейка станет копией первой. Клавиши — это параметр, а не часть змейки.

## Почему тела змеек запоминаются до хода?

- [ ] чтобы игра работала быстрее
- [x] иначе результат зависел бы от того, какую змейку обработали первой
- [ ] чтобы сохранить игру на случай сбоя

> Обе змейки должны играть по одной и той же картине поля. Иначе одна и та же ситуация давала бы разный исход — это нечестно.

## Что происходит при лобовом столкновении?

- [ ] побеждает тот, кто двигался быстрее
- [ ] погибает тот, кто шагнул вторым
- [x] погибают обе змейки

> Формально никто ни в кого не врезался: обе головы оказались в одной клетке. Правило простое — погибают обе, очко не получает никто.

## Почему чужая змейка считается целиком, вместе с хвостом?

- [ ] потому что хвост — самая опасная часть
- [x] потому что ходы одновременные и определить, кто был первым, невозможно
- [ ] потому что так проще рисовать

> У своей змейки последняя клетка не считается: хвост уходит в этот же шаг. С чужой так нельзя — честного порядка нет, значит правило должно быть неоспоримым.

## Сколько побед нужно, чтобы выиграть матч?

- [ ] одна
- [ ] две
- [x] три

> Матч идёт до трёх побед. Больше раундов — меньше влияния случайности.

## Что происходит при ничьей в раунде?

- [ ] очко получают оба игрока
- [x] очко не получает никто, раунд переигрывается
- [ ] матч заканчивается вничью

> Ничья не приближает конец матча: иначе паре, которой ничья выгодна, стало бы выгодно играть на неё.

## Зачем нужна переменная `state`?

- [ ] чтобы хранить счёт матча
- [x] чтобы игра знала, что сейчас происходит: играем, показываем итог или матч окончен
- [ ] чтобы запоминать последнее нажатие

> От состояния зависит и ввод, и обновление, и отрисовка. Такая машина состояний есть в любой игре: меню, игра, пауза, конец.

## Что напечатает программа?

```python
snake = Snake(5, 5, RIGHT, keys, ...)
snake.body = [(5, 5), (4, 5)]
snake.step((6, 5), [])
print(len(snake))
```

- [ ] 1
- [ ] 2
- [x] 3

> Голова встала на клетку с едой, значит хвост не убирается: `pop()` не выполняется, и змейка выросла до трёх клеток.

## Зачем загрузка звука обёрнута в `try` / `except`?

- [ ] чтобы звук играл громче
- [x] чтобы игра работала молча, если звука нет
- [ ] чтобы файлы звуков создавались быстрее

> Звук — не повод ронять игру. На машине без звуковой карты всё должно работать, просто без звука.

## Зачем перед турниром ставят тег?

- [ ] чтобы ускорить игру
- [x] чтобы пометить версию, на которой играли, и после неё не править игру
- [ ] чтобы удалить старые коммиты

> Тег не защищает от изменений, а помечает снимок. Если после турнира кто-то скажет «игра была другая», тег покажет, какая именно.

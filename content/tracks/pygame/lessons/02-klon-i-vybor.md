## Цель

- Понять, почему проект нельзя держать на одном ноутбуке.
- Узнать, что такое коммит и репозиторий.
- Получить общий репозиторий класса в PyCharm.
- Сделать первый коммит и отправить его.
- Понять, что авторство коммита — это настройка, а не человек за клавиатурой.

## Артефакт

В PyCharm открыт проект класса, в нём твоя папка, а последний коммит подписан твоим именем и виден в общей истории.

## Разбор

### Проблема одного ноутбука

Представь, что ты месяц писал игру. Она лежит в папке на ноутбуке.

- Ноутбук сломался — игра пропала.
- Ты сел за другой компьютер в классе — игры нет.
- Ты удалил строку, а через неделю понял, что она была нужна — вернуть нельзя.

Всё это решается одним инструментом.

### Снимок и шкафчик

**Коммит** — это снимок всех файлов проекта в момент времени плюс подпись: кто сделал снимок и зачем. Снимки складываются в цепочку, и можно посмотреть любой старый.

**Репозиторий** — это папка проекта вместе со всей историей снимков. Не «папка с файлами», а папка плюс её память.

> [!подсказка]
> Шкафчик. Файлы — то, что лежит на полке сейчас. Коммиты — полки с прошлыми версиями. Репозиторий — весь шкаф.

### Локальная копия и общая

Репозиторий живёт на сервере. Чтобы работать, ты делаешь себе его копию — **клонируешь**.

- **Удалённый** репозиторий — тот, что на сервере. Общий для класса.
- **Локальный** — твоя копия на ноутбуке.

Копия у каждого своя, история общая. Именно поэтому проект доступен с любого ноутбука: клонируешь заново и получаешь всё, что было.

### Кто ты для git

В каждом коммите записаны имя и почта автора. Это не логин на сервере и не учётка Windows — это две строки настройки:

```bash
git config user.name "Иван Петров"
git config user.email "ivan@example.com"
```

В классе ноутбуки общие, и под одной учёткой Windows сидят разные люди. Если не сказать git, кто ты, все коммиты будут подписаны одним человеком, и история превратится в кашу. Поэтому у нас есть маленький скрипт `select-me`: запускаешь — и git знает, кто работает.

> [!важно]
> Настройка пишется **в репозиторий**, а не в компьютер. Так и нужно: репозиторий общий, а люди разные.

### Круг, который повторяется весь год

1. `Update Project` — забрать то, что сделали другие, пока тебя не было.
2. Работаешь: пишешь код, запускаешь, чинишь.
3. `Commit` — сделать снимок с подписью.
4. `Push` — отправить снимок на сервер.

Этот круг не меняется. Меняется только код внутри.

## Код

Правь свой файл и запускай кнопкой ▶, как в прошлом уроке:

```python
print("Привет! Я запускаюсь из PyCharm.")
print("Это мой первый файл в общем репозитории класса.")
```

Теперь отправь работу. В PyCharm это делается мышкой, а команды полезно знать, чтобы понимать, что происходит.

### Забрать репозиторий

`File` → `New` → `Project from Version Control`, вставить ссылку, которую дал учитель, нажать `Clone`.

Под капотом выполняется:

```bash
git clone <ссылка на репозиторий класса>
```

PyCharm спросит, доверяешь ли ты проекту, — отвечай `Trust Project`. Затем найди папку со своим именем.

### Представиться

Открой вкладку `Terminal` внизу PyCharm и запусти:

```bash
.\select-me
```

Скрипт спросит твой логин и подпишет коммиты твоим именем.

`.\` перед именем означает «файл в этой папке». Так пишут в PowerShell. В cmd сработает и просто `select-me`, но форма с точкой работает в обеих оболочках, поэтому привыкай к ней. На macOS и Linux то же самое выглядит как `./select-me`.

Это единственный раз, когда мы осознанно пользуемся терминалом: у этой операции нет кнопки.

### Сделать снимок

- Панель `Commit` — слева, значок с галочкой, или `Ctrl+K`.
- В списке отметь файлы, которые войдут в снимок. Пока отмечаем всё своё.
- Внизу напиши сообщение: `Добавил приветствие в свой файл`.
- Нажми `Commit`.

Под капотом:

```bash
git add .
git commit -m "Добавил приветствие в свой файл"
```

### Отправить

- `Ctrl+Shift+K` или меню `Git` → `Push`.

Под капотом:

```bash
git push
```

Готово: твоя работа уехала на сервер и видна всем.

> [!важно]
> Сообщение коммита пишут так, чтобы через месяц было понятно, что произошло. «изменения» и «фикс» не говорят ничего. «Добавил приветствие в свой файл» говорит всё.

## Гит

```bash
# один раз: получить репозиторий класса
git clone <ссылка>

# каждый урок: представиться и забрать чужое
.\select-me
git pull

# после работы
git add .
git commit -m "короткое описание того, что сделал"
git push
```

В PyCharm то же самое: `Project from Version Control` → `Terminal` для `select-me` → `Commit` → `Push`. Команды знать стоит: когда-нибудь ты уйдёшь из PyCharm, а git останется тем же.

## Шпаргалка

### Что должно работать

- Репозиторий класса открыт в PyCharm, видна своя папка
- `select-me` подписал коммиты твоим именем
- Коммит отправлен кнопкой `Push`, панель `Commit` пуста

### Запомнить

- **Коммит** — снимок файлов плюс подпись: кто и зачем.
- **Репозиторий** — файлы вместе со всей историей снимков.
- **Push** отправляет твою работу на сервер, **Update Project** забирает чужую.

### Команды

```bash
git clone <ссылка>          # получить репозиторий один раз
git pull                    # забрать чужое в начале урока
git add .                   # отметить файлы для снимка
git commit -m "сообщение"   # сделать снимок
git push                    # отправить на сервер
```

## Для учителя

- До урока нужно создать репозиторий класса и раздать ссылку. Структура: папка на каждого ученика, общий `README.md`, скрипты `select-me.cmd` и `select-me` в корне.
- На общих ноутбуках держите один токен класса, иначе каждый будет вводить доступ заново. Авторство при этом остаётся правильным: его задаёт `select-me`, а не токен.
- На Windows PyCharm не умеет хранить пароли в системном хранилище и предлагает KeePass. Самый предсказуемый вариант — дать классу один токен и включить запоминание, иначе каждый `push` будет требовать ввода.
- Первый `Push` — самый рискованный момент урока. Пройди по машинам и убедись, что он прошёл.
- Если кто-то запушит раньше остальных, это хорошо: у соседей `Update Project` начнёт что-то приносить, и смысл команды станет осязаемым.
- Про git-терминал: в PyCharm он есть, но не обязателен. Достаточно знать, какая кнопка какой команде соответствует.

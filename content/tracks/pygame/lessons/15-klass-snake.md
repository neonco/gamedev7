## Цель

- Понять, зачем нужен класс, когда объектов становится несколько.
- Перенести логику змейки в методы.
- Освоить `__init__` и `self` на своём коде, а не на примере.
- Оставить правила взаимодействия снаружи класса.

## Артефакт

Одна змейка, но теперь это объект класса `Snake`. Игра играется ровно как раньше — мы ничего не сломали, только переложили код.

## Разбор

### Зачем это сейчас

В прошлом блоке змейка была набором переменных: `snake`, `direction`, `pending`, `alive`. Работало нормально, пока змейка одна.

На следующем уроке их станет две. И тут начинается беда: придётся завести `snake2`, `direction2`, `pending2` — и каждую функцию писать дважды. А если змеек станет три, писать трижды.

**Класс решает ровно эту задачу:** один раз описываем, как устроена змейка, и создаём сколько нужно.

> [!подсказка]
> Класс — чертёж, объект — изделие по чертежу. Чертёж один, змеек по нему можно сделать сколько угодно, и каждая будет со своим телом и своим направлением.

### Что переезжает в класс

Всё, что описывает **одну** змейку:

| Было | Стало |
|---|---|
| `snake = [...]` | `self.body` |
| `direction`, `pending` | `self.direction`, `self.pending` |
| `alive` | `self.alive` |
| `score` | `self.eaten` |
| `move(...)` | `self.step(...)` |
| `direction_from_key(...)` | `self.turn(...)` |
| `draw_snake(...)` | `self.draw(...)` |

### Что остаётся снаружи

Правила взаимодействия змеек: столкновения друг с другом, лоб в лоб, кто победил в раунде. Класс `Snake` отвечает **только за себя** и про других не знает.

Это не формальность, а вопрос здравого смысла: если змейка начнёт сама решать, кто победил, то при двух змейках обе будут решать это одновременно и по-разному.

### self

`self` — это «эта конкретная змейка». Внутри класса нельзя написать просто `body`, потому что непонятно, чьё это тело. Пишем `self.body` — «тело вот этой змейки».

Внутри метода `self` всегда первый параметр, а при вызове его не пишут:

```python
snake.turn(pygame.K_w)     # не snake.turn(snake, pygame.K_w)
```

### __init__

`__init__` — что происходит, когда змейка рождается. Здесь задаём начальное состояние: где стоит, куда смотрит, какие клавиши слушает.

На этом уроке клавиши ещё не нужны, поэтому просто запомним их параметром — они понадобятся на следующем.

## Код

Создай класс и перенеси в него логику. Начни с такого вида:

```python
class Snake:
    """Одна змейка. Про другую ничего не знает."""

    def __init__(self, x, y, direction, keys, color, head_color, name):
        self.body = [(x, y)]
        self.direction = direction
        self.pending = direction
        self.keys = keys                  # (вверх, вниз, влево, вправо)
        self.color = color
        self.head_color = head_color
        self.name = name
        self.alive = True
        self.eaten = 0                    # сколько съела за раунд
```

Дальше перенеси в методы то, что раньше было функциями. Логика не меняется — меняется только то, что данные берутся из `self`.

```python
    def next_head(self):
        x, y = self.body[0]
        dx, dy = self.pending
        return (x + dx, y + dy)

    def step(self, food):
        """Шаг змейки."""
        head = self.next_head()

        if head[0] < 0 or head[0] >= COLS or head[1] < 0 or head[1] >= ROWS:
            self.alive = False
            return False

        if head in self.body[:-1]:
            self.alive = False
            return False

        self.direction = self.pending
        self.body = [head] + self.body
        ate = head == food
        if ate:
            self.eaten += 1
        else:
            self.body.pop()
        return ate

    def draw(self, surface):
        for index, cell in enumerate(self.body):
            if index == 0:
                color = self.head_color
            else:
                color = self.color
            rect = cell_rect(cell)
            pygame.draw.rect(surface, color, rect)
            pygame.draw.rect(surface, BG_DARK, rect, 2)
```

И поворот:

```python
    def turn(self, key):
        """Повернуть, если клавиша про движение и разворот не запрещён."""
        for index, code in enumerate(self.keys):
            if key != code:
                continue
            new = (UP, DOWN, LEFT, RIGHT)[index]
            if (new[0] + self.direction[0], new[1] + self.direction[1]) == (0, 0):
                return
            self.pending = new
            return
```

Направления вынеси в константы, чтобы не путаться:

```python
UP = (0, -1)
DOWN = (0, 1)
LEFT = (-1, 0)
RIGHT = (1, 0)
```

И замени старый код создания змейки на одну строку:

```python
snake = Snake(4, ROWS // 2, RIGHT,
              (pygame.K_w, pygame.K_s, pygame.K_a, pygame.K_d),
              (60, 90, 200), (40, 60, 160), "Игрок 1")
```

В игровом цикле вызовы тоже меняются:

```python
        if state == "play":
            for snake in [snake]:
                snake.turn(event.key)
```

```python
            if snake.step(food):
                food = new_food([snake])
```

Не забудь убрать старые функции `move`, `direction_from_key`, `draw_snake`: их работу теперь делают методы.

> [!важно]
> После рефакторинга игра должна играться **точно так же**. Если что-то изменилось в поведении — ты не перенёс код, а переписал его. Старую версию всегда можно достать: она под тегом `block-2`.

### Методы, которые Python вызывает сам

Класс уже приносит пользу, но у него есть возможность, которой не было у обычных функций.

Некоторые методы носят имена в двойных подчёркиваниях. Их не надо вызывать — Python вызывает их сам, когда видит знакомую операцию.

```python
    def __len__(self):
        """len(snake) — длина змейки."""
        return len(self.body)

    def __str__(self):
        """print(snake) покажет состояние: удобно для отладки."""
        return (
            f"{self.name}: длина {len(self.body)}, направление {self.direction}, "
            f"съедено {self.eaten}, жива {self.alive}"
        )
```

- `__len__` включается, когда ты пишешь `len(snake)`. Раньше пришлось бы писать `len(snake.body)` — а теперь длина стала частью самой змейки.
- `__str__` включается, когда змейка попадает в `print` или в f-строку. Вместо непонятного `<Snake object at 0x104f3a1d0>` напечатается состояние.

Проверь: добавь `print(player1)` в любое место программы и посмотри, что выведется. Это удобный способ отладки — не нужно вручную собирать строку из `body`, `eaten` и `alive`.

> [!подсказка]
> Такие методы называют магическими: снаружи они выглядят как обычные операции, а внутри работает твой код. Но перегружать всё подряд не надо — если метод не делает класс удобнее, он только запутывает.

- Главная проверка: поведение не изменилось. Если что-то поехало — сравни с тегом `block-2`, там рабочая одиночная версия.
- Не позволяй оставлять старые функции «на всякий случай». Два способа делать одно и то же — источник путаницы.
- Если кто-то спрашивает, зачем `keys` в конструкторе, хотя клавиши пока одни: ответ — на следующем уроке.
- Про магические методы говори ровно столько, сколько нужно: `__len__` и `__str__` по делу, остальное — за пределами курса. Полноценная перегрузка арифметики здесь негде оправдается, а зубрить синтаксис ради синтаксиса мы договорились не делать.
- `__str__` — это инструмент отладки, и это стоит подчеркнуть: `print(snake)` экономит время, когда непонятно, что происходит с игрой.

## Цель

- Создать второй объект из того же класса.
- Понять, что клавиши — это параметр, а не часть класса.
- Сделать одновременный ход обеих змеек.
- Разобраться, почему ходы считаются по одной картине поля.

## Артефакт

Игрок 1 управляет клавишами W A S D, игрок 2 — стрелками. Змейки ползают одновременно и не мешают друг другу.

## Разбор

### Один класс — два объекта

Класс у нас уже есть, поэтому вторая змейка — это одна строка:

```python
player1 = Snake(4, ROWS // 2, RIGHT, (pygame.K_w, pygame.K_s, pygame.K_a, pygame.K_d), ...)
player2 = Snake(COLS - 5, ROWS // 2, LEFT, (pygame.K_UP, pygame.K_DOWN, pygame.K_LEFT, pygame.K_RIGHT), ...)
```

Обрати внимание: класс один и тот же, а объекты разные. У каждого своё тело, своё направление, свой счёт. Это и есть смысл классов — мы уже видели это на примере, теперь делаем сами.

### Клавиши — это параметр

Соблазн написать внутри класса «игрок 1 слушает WASD» велик. Но тогда класс будет знать, кто им управляет, и вторая змейка станет копией первой.

Правильно — передать клавиши снаружи. Змейка просто знает, какие четыре клавиши её слушают, и ей всё равно, кто за ними сидит.

Порядок клавиш в кортеже важен и совпадает с порядком направлений:

```python
keys = (клавиша вверх, клавиша вниз, клавиша влево, клавиша вправо)
UP, DOWN, LEFT, RIGHT = (0, -1), (0, 1), (-1, 0), (1, 0)
```

### Ходы одновременные

Змейки ходят в один и тот же момент. Это создаёт тонкость, из-за которой игры с двумя змейками ломаются.

Представь: первая змейка шагает первой и встаёт на клетку, которую вторая только что покинула. Если считать по очереди, первая погибнет. А если шагнуть в обратном порядке — погибнет вторая. Одна и та же ситуация, разный результат — это нечестно.

Решение: **сначала запомнить положение обеих змеек, и только потом двигать**.

```python
bodies = [snake.body for snake in snakes]
```

Теперь обе змейки играют по одной и той же картине поля, и порядок перебора ничего не решает.

### Лоб в лоб

Если обе головы идут в одну и ту же клетку, ни одна из них ни в кого не врезалась — но они врезались друг в друга. Это надо проверить отдельно:

```python
head_on = heads[0] is not None and heads[0] == heads[1]
```

При лобовом столкновении погибают обе. Подробнее — в правилах: [[pravila]].

## Код

Функция новой расстановки:

```python
def new_round():
    """Свежие змейки в противоположных концах поля, смотрят друг на друга."""
    player1 = Snake(4, ROWS // 2, RIGHT,
                    (pygame.K_w, pygame.K_s, pygame.K_a, pygame.K_d),
                    (60, 90, 200), (40, 60, 160), "Игрок 1")
    player2 = Snake(COLS - 5, ROWS // 2, LEFT,
                    (pygame.K_UP, pygame.K_DOWN, pygame.K_LEFT, pygame.K_RIGHT),
                    (230, 150, 60), (190, 110, 30), "Игрок 2")
    snakes = [player1, player2]
    return snakes, new_food(snakes)
```

Обрати внимание: `new_food` теперь принимает **список** змеек, потому что еда не должна появиться ни в одной из них.

Общий шаг обеих змеек:

```python
def step_snakes(snakes, food):
    """Один общий шаг обеих змеек.

    Сначала запоминаем тела до хода, чтобы обе змейки играли по одной
    и той же картине поля. Лобовое столкновение убивает обеих.
    """
    bodies = [snake.body for snake in snakes]
    heads = []
    for snake in snakes:
        if snake.alive:
            heads.append(snake.next_head())
        else:
            heads.append(None)

    head_on = heads[0] is not None and heads[0] == heads[1]

    ate = False
    for index, snake in enumerate(snakes):
        if not snake.alive:
            continue
        if head_on:
            snake.alive = False
            continue
        obstacles = [bodies[i] for i in range(len(snakes)) if i != index]
        if snake.step(food, obstacles):
            ate = True
    return ate
```

Заметь: метод `step` теперь принимает `obstacles` — тела других змеек. Внутрь самого класса мы заглядывать не стали: класс по-прежнему ничего не знает о других змейках, ему просто сообщают, где они.

Ввод: клавиша достаётся обеим змейкам, и каждая решает сама, её это клавиша или нет.

```python
            elif event.type == pygame.KEYDOWN:
                for snake in snakes:
                    if snake.alive:
                        snake.turn(event.key)
```

Дополни `Snake.step` проверкой чужих тел — она уже есть в сигнатуре, но тело проверки добавим на следующем уроке вместе с правилами.

## Шпаргалка

### Что должно работать

- Две змейки на поле, каждая со своим цветом
- WASD двигает первую, стрелки — вторую
- Они могут ползать одновременно, не мешая друг другу

### Запомнить

- Один класс — сколько угодно объектов. У каждого свои данные.
- Клавиши передаются в конструктор: класс не знает, кто им управляет.
- Порядок клавиш в кортеже совпадает с порядком направлений.
- Ходы одновременные: сначала снимок тел, потом движение. Иначе исход зависит от порядка перебора.
- Лоб в лоб — отдельная проверка, погибают обе.

### Проверьте вместе

Спросите, почему клавиши передаются в змейку снаружи, а не записаны внутри класса.

## Для учителя

- Момент с одновременным ходом — самое ценное в уроке. Он объясняет, почему «просто по очереди» не годится, и это понимание пригодится в любой сетевой игре.
- Проверь, что `obstacles` передаётся, а не читается из глобальной переменной: иначе класс снова начнёт знать лишнее.
- Если кто-то сделал два разных класса `Snake1` и `Snake2` — разбери, чем это плохо: любое исправление придётся делать дважды.

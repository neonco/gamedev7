## Цель

- Собрать запуск новой игры в одну функцию.
- Перезапускать игру по клавише, не закрывая окно.
- Ускорять змейку по мере роста.
- Понять, почему важно сбрасывать всё состояние, а не только часть.

## Артефакт

После смерти нажатие R начинает новую игру: змейка короткая и медленная, счёт обнулён. По ходу игры змейка постепенно ускоряется.

## Разбор

### Одна функция вместо десяти строк

Сейчас начало игры размазано по файлу: где-то создаётся змейка, где-то еда, где-то счёт. Чтобы начать заново, придётся повторить все эти строки — а повторить и забыть половину очень легко.

Соберём начало игры в функцию:

```python
def new_game():
    """Начальное состояние игры."""
    snake = [(COLS // 2, ROWS // 2)]
    direction = (1, 0)
    return snake, direction, new_food(snake), 0, True
```

Пять значений по порядку: змейка, направление, еда, счёт, признак жизни.

> [!важно]
> Возвращать пять значений сразу — нормально, но забирать их надо строго в том же порядке. Перепутаешь — получишь еду в переменной для счёта и будешь долго искать, почему счёт стал кортежем.

### Что значит «сбросить игру»

Начать заново — это не только вернуть змейку в центр. Есть ещё три вещи, которые живут отдельно от неё:

- `pending` — куда повернём на следующем шаге;
- `tick` — текущая скорость;
- `last_move` — когда был последний шаг.

Если забыть сбросить `pending`, новая змейка сразу поедет в ту сторону, куда игрок нажал перед смертью. Мелочь, но выглядит как поломка.

А если забыть `last_move`, шаг может произойти мгновенно после перезапуска. Тоже мелочь, и тоже заметная.

### Скорость как переменная

До сих пор скорость была настройкой `START_TICK`. Теперь сделаем её переменной, которая меняется по ходу игры:

```python
tick = START_TICK
...
    if ate:
        tick = max(MIN_TICK, tick - 5)
```

Читается так: ставим скорость чуть быстрее, но не быстрее `MIN_TICK`. `max` выбирает большее из двух чисел — то есть не даёт скорости стать слишком маленькой.

Помни: **меньше число — быстрее змейка**. `TICK` — это пауза между шагами в миллисекундах.

Без ограничения `MIN_TICK` змейка через полсотни съеденных кружков стала бы такой быстрой, что пауза обнулилась бы, и она полетела бы с частотой кадров. Играть стало бы невозможно.

### Почему рестарт только после смерти

Нажатие R обрабатывается с условием:

```python
if event.key == pygame.K_r and not alive:
```

Иначе игрок случайно перезапускал бы игру посреди партии. Это правило: новая игра начинается, когда старая закончилась.

## Код

Добавь настройку самого быстрого шага:

```python
MIN_TICK = 60             # быстрее этого змейка не поползёт
```

Добавь функцию начала игры:

```python
def new_game():
    """Начальное состояние игры."""
    snake = [(COLS // 2, ROWS // 2)]
    direction = (1, 0)
    return snake, direction, new_food(snake), 0, True
```

Замени подготовку перед циклом:

```python
snake, direction, food, score, alive = new_game()
pending = direction          # куда повернём на следующем шаге
tick = START_TICK            # текущая скорость
last_move = pygame.time.get_ticks()
```

Замени обработку нажатий целиком — теперь клавиша R умеет начинать заново:

```python
    for event in pygame.event.get():
        if event.type == pygame.QUIT:
            running = False
        elif event.type == pygame.KEYDOWN:
            if event.key == pygame.K_r and not alive:
                snake, direction, food, score, alive = new_game()
                pending = direction
                tick = START_TICK
                last_move = pygame.time.get_ticks()
            elif alive:
                new_direction = direction_from_key(event.key, direction)
                if new_direction is not None:
                    pending = new_direction
```

Обрати внимание: ветка `elif alive` — пока змейка жива, клавиши управляют, а после смерти только R работает.

В обновлении замени `START_TICK` на переменную и добавь ускорение:

```python
    if alive:
        now = pygame.time.get_ticks()
        if now - last_move >= tick:
            last_move = now
            direction = pending
            snake, ate, alive = move(snake, direction, food)
            if ate:
                score += 1
                food = new_food(snake)
                tick = max(MIN_TICK, tick - 5)
```

Добавь подсказку на экран проигрыша, чтобы игрок знал про R:

```python
def draw_game_over():
    text = font.render("Игра окончена. R — заново", True, TEXT_COLOR)
    rect = text.get_rect(center=(WIDTH // 2, HEIGHT // 2))
    pygame.draw.rect(screen, BG_LIGHT, rect.inflate(30, 20))
    screen.blit(text, rect)
```

Проверь: съешь пять кружков и почувствуй, что змейка ускорилась. Потом умри и начни заново по R — скорость должна вернуться к начальной.

## Шпаргалка

### Что должно работать

- Клавиша R начинает новую игру, окно не перезапускается
- После рестарта счёт обнулён, змейка короткая и медленная
- По ходу игры змейка ускоряется, но не до невозможного

### Запомнить

- Начало игры собрано в функцию `new_game`, чтобы не повторять строки.
- При рестарте сбрасывается **всё**: змейка, еда, счёт, направление, `pending`, скорость, `last_move`.
- `max(MIN_TICK, tick - 5)` не даёт скорости стать слишком большой.
- **Меньше `TICK` — быстрее змейка.**

### Проверьте вместе

Спросите, что забудешь сбросить, если сбросить только змейку и счёт.

## Для учителя

- Мысль «сбросить всё состояние, а не только видимую часть» — главная здесь. Пусть ребёнок специально забудет сбросить `pending` и увидит, как новая змейка сразу уезжает вбок.
- `max` против `min` — частая путаница. Проверь, что все понимают: `max` не даёт числу упасть ниже порога.
- Пауза в домашке требует третьей переменной состояния. Это хорошая подготовка к мысли, что у игры есть режимы: играем, пауза, конец, меню.

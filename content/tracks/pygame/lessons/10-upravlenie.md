## Цель

- Обрабатывать нажатия клавиш через события.
- Понять, почему направление меняется не сразу, а на следующем шаге.
- Запретить разворот на 180 градусов.
- Сразу поддерживать две раскладки: стрелки и WASD.

## Артефакт

Змейкой можно управлять стрелками или клавишами W, A, S, D. Нажать «влево», когда ползёшь вправо, — бесполезно: змейка не развернётся в себя.

## Разбор

### Событие вместо опроса

Есть два способа узнать, что нажата клавиша.

**Опрос состояния**: `pygame.key.get_pressed()` — «какие клавиши зажаты прямо сейчас». Хорош для непрерывного движения: пока держишь стрелку, ракета летит.

**Событие**: `pygame.event.get()` — «что произошло с прошлого кадра». Хорош для одиночных действий: выстрел, прыжок, поворот.

Нам нужно второе. Поворот — это одиночное действие, а не «держу и поворачиваюсь». Событие нажатия выглядит так:

```python
if event.type == pygame.KEYDOWN:
    ...
```

`KEYDOWN` приходит в момент нажатия. Клавиша лежит в `event.key`.

### Почему направление меняется не сразу

Кажется логичным написать так: нажали — сразу поменяли `direction`. Но это ломает игру.

Вспомни: змейка двигается **только на тиках**, шесть-семь раз в секунду. А нажать клавишу игрок может успеть несколько раз между двумя тиками. И тогда происходит вот что.

Змейка ползёт вправо. За одну долю секунды до шага игрок жмёт «вверх», а сразу за этим «влево». Если менять направление мгновенно, то:

- нажали «вверх»: направление вверх. Проверка разворота пропускает — вверх не противоположно вправо;
- нажали «влево»: направление влево. Проверка тоже пропускает — влево не противоположно вверх.

Каждое нажатие по отдельности законно. А вместе они дают разворот на 180 градусов: змейка ползла вправо, а теперь поедет влево — прямо в собственное тело. Игра закончится мгновенно, и игрок не поймёт, что сделал не так.

Главное правило: **за один шаг змейка поворачивает один раз**. Значит, направление нужно менять не в момент нажатия, а в момент шага. Поэтому нажатия мы копим в отдельной переменной:

```python
pending = direction      # куда повернём на следующем шаге
```

В обработчике события обновляем только `pending` — сколько угодно раз, сработает последнее нажатие. А на шаге, когда змейка двигается, `pending` становится её направлением:

```python
direction = pending
snake = move(snake, direction)
```

И ещё одна тонкость: разворот проверяется против `direction` — того направления, в котором змейка **реально ползёт сейчас**, а не против `pending`. Иначе проверка смотрела бы на то, что ещё не случилось.

Так между двумя шагами можно нажимать сколько угодно — сработает только последнее нажатие, и разворот в себя невозможен.

### Запрет разворота

Два направления противоположны, если их сумма — `(0, 0)`:

```python
if (new[0] + current[0], new[1] + current[1]) == (0, 0):
    return None
```

Вправо — это `(1, 0)`, влево — `(-1, 0)`. Сумма `(0, 0)`. Значит, разворот.

### Зачем сразу WASD

Стрелки и WASD делают одно и то же — это одна функция, которая переводит клавишу в направление.

Это не лишняя работа, а задел: когда появится второй игрок, у него будут WASD, а у первого стрелки. Мы просто заранее позаботились о том, чтобы обе раскладки уже работали.

## Код

Добавь функцию перевода клавиши в направление:

```python
def direction_from_key(key, current):
    """Какое направление задаёт клавиша. None — если клавиша не про движение."""
    if key in (pygame.K_UP, pygame.K_w):
        new = (0, -1)
    elif key in (pygame.K_DOWN, pygame.K_s):
        new = (0, 1)
    elif key in (pygame.K_LEFT, pygame.K_a):
        new = (-1, 0)
    elif key in (pygame.K_RIGHT, pygame.K_d):
        new = (1, 0)
    else:
        return None

    # разворот на 180 градусов запрещён
    if (new[0] + current[0], new[1] + current[1]) == (0, 0):
        return None
    return new
```

Перед циклом добавь запомненное направление:

```python
pending = direction      # куда повернём на следующем шаге
```

В обработку ввода — реакцию на нажатие:

```python
    for event in pygame.event.get():
        if event.type == pygame.QUIT:
            running = False
        elif event.type == pygame.KEYDOWN:
            new_direction = direction_from_key(event.key, direction)
            if new_direction is not None:
                pending = new_direction
```

В обновление — применение поворота перед шагом:

```python
    now = pygame.time.get_ticks()
    if now - last_move >= START_TICK:
        last_move = now
        direction = pending
        snake = move(snake, direction)
```

Остальной файл не меняется.

Проверь:

- поелозь стрелками, потом WASD;
- попробуй развернуться на 180 градусов — не получится, и это правильно;
- быстро нажми «вверх» и «влево» подряд: змейка повернёт один раз, а не дважды.

### Запомнить

- **KEYDOWN** — событие «клавишу нажали». `get_pressed` — «клавиша зажата сейчас».
- Направление меняется **на шаге**, а не в момент нажатия. Иначе двумя нажатиями между шагами можно развернуться в себя.
- `pending` — куда повернём на следующем шаге.
- Два направления противоположны, если их сумма `(0, 0)`.

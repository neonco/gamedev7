## Цель

- Добавить столкновения змеек друг с другом.
- Понять, почему чужая змейка считается целиком, вместе с хвостом.
- Определить победителя раунда.
- Зафиксировать правила так, чтобы на турнире не возникало споров.

## Артефакт

Змейка погибает, врезавшись в соперника, — и в лоб, и в бок. Раунд заканчивается, определяется победитель. Правила записаны в документе [[pravila]].

## Разбор

### Четыре способа погибнуть

У змейки на двоих их больше, чем в одиночной игре:

1. Врезалась в стену.
2. Укусила себя.
3. Врезалась в тело соперника.
4. Столкнулась с соперником лоб в лоб.

Первые два мы уже умеем. Третье добавляется одной проверкой:

```python
for body in obstacles:
    if head in body:
        self.alive = False
        return False
```

Четвёртое проверяется отдельно, потому что формально никто ни в кого не врезался: обе головы просто оказались в одной клетке.

### Почему чужая змейка считается целиком

В одиночной игре мы проверяли `self.body[:-1]` — без последней клетки. Логика была такая: хвост в этот же шаг уходит, значит, заходить на его клетку можно.

С чужой змейкой так не получится. Обе змейки ходят **одновременно**, и определить, кто шагнул первым, невозможно. Если разрешить заходить на клетку чужого хвоста, начнутся споры: один говорит «я успел», другой — «нет, это я успел».

Поэтому правило простое и одинаковое для всех: **чужая змейка считается целиком**. Заход на клетку, где был её хвост, — смерть.

> [!важно]
> Это не про справедливость в смысле «кто первый», а про отсутствие споров. Правило, которое нельзя оспорить, лучше правила, которое «точнее», но требует судьи на каждом шаге.

### Сначала смерть, потом еда

Порядок проверок важен: сначала стены и столкновения, и только потом еда. Погибшая змейка еду не получает и не растёт, даже если голова оказалась ровно на клетке с едой.

Проверь у себя: в методе `step` возврат `self.alive = False` стоит **до** строки, где считается `ate`. Если у тебя наоборот — сначала растёт, потом умирает.

### Кто победил в раунде

Правило на все случаи:

```python
def round_result(snakes):
    """Кто победил в раунде: 0, 1 или None при ничьей."""
    alive = [snake for snake in snakes if snake.alive]
    if len(alive) == 1:
        return snakes.index(alive[0])
    # либо погибли обе, либо время вышло — решает еда за раунд
    if snakes[0].eaten > snakes[1].eaten:
        return 0
    if snakes[1].eaten > snakes[0].eaten:
        return 1
    return None
```

`None` означает ничью: очко не получает никто, раунд переигрывается.

### Зачем записывать правила отдельно

Правила — это не только код. Это ещё и документ, который читают до турнира: игроки, учитель, родители.

Если правила живут только в коде, то на первом же спорном моменте придётся вчитываться в программу и спорить о её поведении. А если правила записаны заранее — спор решается одним абзацем.

Документ: [[pravila]]. Прочитай его целиком, там разобраны случаи, до которых мы ещё не дошли.

## Код

Добавь в `Snake.step` проверку чужих тел:

```python
    def step(self, food, obstacles):
        """Шаг змейки. obstacles — тела других змеек до их хода."""
        head = self.next_head()

        if head[0] < 0 or head[0] >= COLS or head[1] < 0 or head[1] >= ROWS:
            self.alive = False
            return False

        # своё тело без последней клетки: хвост в этот же шаг уходит
        if head in self.body[:-1]:
            self.alive = False
            return False

        # чужая змейка считается целиком, вместе с хвостом
        for body in obstacles:
            if head in body:
                self.alive = False
                return False

        self.direction = self.pending
        self.body = [head] + self.body
        ate = head == food
        if ate:
            self.eaten += 1
        else:
            self.body.pop()
        return ate
```

Добавь определение победителя раунда:

```python
def round_result(snakes):
    """Кто победил в раунде: 0, 1 или None при ничьей."""
    alive = [snake for snake in snakes if snake.alive]
    if len(alive) == 1:
        return snakes.index(alive[0])
    if snakes[0].eaten > snakes[1].eaten:
        return 0
    if snakes[1].eaten > snakes[0].eaten:
        return 1
    return None
```

И остановку раунда в игровом цикле:

```python
            dead = any(not snake.alive for snake in snakes)
            if dead:
                winner = round_result(snakes)
                if winner is None:
                    result_text = ["Ничья в раунде", "Раунд переигрывается"]
                else:
                    result_text = [f"{snakes[winner].name} берёт раунд"]
                state = "between"
                continue
```

Проверь все четыре вида смерти:

- врежься в стену;
- вырасти до пяти клеток и укуси себя;
- врежься в бок соперника;
- договорись с соседом и столкнитесь лбами: должны погибнуть обе.

## Шпаргалка

### Что должно работать

- Все четыре вида смерти: стена, своё тело, чужое тело, лоб в лоб
- Победа в раунде присуждается по правилам
- При равных очках — ничья, раунд переигрывается

### Запомнить

- **Чужая змейка считается целиком**, включая хвост. Ходы одновременные, честного порядка нет, поэтому правило не должно требовать судьи.
- У своей змейки последняя клетка не считается: там хвост уходит.
- **Сначала смерть, потом еда.** Погибшая еду не получает.
- Правила живут не только в коде, но и в документе — чтобы споры решались до турнира, а не во время.

## Для учителя

- Главная мысль урока — не про код, а про то, что правило должно быть неоспоримым. Разбери это на примере чужого хвоста: «точное» правило потребовало бы определять, кто шагнул первым, а это невозможно.
- Домашка с поиском неописанного случая — проверка на понимание. Хорошие ответы: что если обе змейки одновременно съели одну еду; что если змейка умерла, но её тело осталось на поле и в него кто-то врезался.
- Не пропускай чтение документа правил: на турнире именно на него будут ссылаться.

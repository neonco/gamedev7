## Артефакт

Игра помечена тегом `v1.0-tournament`. Регламент [[reglament]] прочитан и лежит распечатанным. Сетка построена. Матч проходит от начала до конца без сбоев.

## Разбор

### Олимпийская система

Это игра на вылет: проиграл матч — выбыл. Такой формат хорош тем, что турнир короткий: на 20 человек всего 19 матчей, а не 190, как при игре каждого с каждым.

Обратная сторона — случайность. Один неудачный раунд, и сильный игрок выбывает. Поэтому матч играют не из одного раунда, а до трёх побед: так случайность влияет меньше.

### Почему регламент нужен до турнира

Правила игры мы зафиксировали в [[pravila]] — они отвечают на вопрос «что происходит на поле». Регламент отвечает на другие вопросы:

- кто с кем играет и как это решается;
- что делать, если участников нечётное число;
- сколько это займёт времени;
- кто судит и что делать при споре;
- что если завис ноутбук или кто-то опоздал.

Эти вопросы обязательно возникнут. Если ответа нет заранее, решение будет принято в спешке — и кому-то покажется несправедливым.

### Проход без игры

Если участников нечётное число, кто-то в первом круге остаётся без соперника и проходит дальше без игры. Это называется bye.

Важно, чтобы таких участников не свели друг с другом: иначе они просто простаивают, а турнир теряет время. Поэтому пустые места в сетке распределяются по жребию, а не подряд.

### Сетка

Сетку можно нарисовать руками, а можно построить скриптом: `tools/make_bracket.py` в репозитории курса берёт список участников и делает печатную сетку. Соперники расставляются случайно, проходы без игры распределяются по правилам.

Скрипт запускается один раз, в день турнира, при всех:

```bash
python3 tools/make_bracket.py students.txt
```

Результат — страница, которую можно распечатать и повесить.

### Заморозка версии

Последнее и самое важное: **турнирная версия должна перестать меняться**.

Пока идёт турнир, кто-то обязательно захочет поправить «одну мелочь» в игре. Этого делать нельзя: если разные пары играют на разных версиях, результаты несравнимы.

Поэтому перед турниром ставим тег:

```bash
git tag v1.0-tournament
git push --tags
```

В PyCharm: меню `Git` → `New Tag`, имя `v1.0-tournament`, затем `Push` с галочкой `Push tags`.

После этого изменить игру можно, но тег останется на старом снимке. На турнире играем на версии под тегом — и если кто-то спросит, всегда можно показать, какая именно версия играла.

> [!важно]
> Тег не защищает от изменений, он их **помечает**. Заморозка — это договорённость: после тега никто не правит игру, а если правит, то это уже другая версия и играть на ней нельзя.

## Код

Заморозка версии:

```bash
git pull
git add .
git commit -m "Версия для турнира: матч до трёх побед, звук, экран результата"
git tag v1.0-tournament
git push
git push --tags
```

Построение сетки (один раз, в день турнира):

```bash
python3 tools/make_bracket.py students.txt
```

### Генеральная репетиция

Перед турниром сыграй два-три матча целиком, по правилам, и проверь по списку:

- раунд заканчивается и по смерти, и по времени;
- ничья не засчитывается никому и раунд переигрывается;
- матч заканчивается после трёх побед;
- R начинает новый матч, счёт обнуляется;
- звук есть на всех действиях;
- игра не падает, если убрать папку `sounds`;
- обе змейки одинаково быстрые.

> [!подсказка]
> Репетиция нужна не для галочки. Проблемы, которые находятся на репетиции, стоят пяти минут; те же проблемы в середине турнира стоят всего турнира.

## Для учителя

- Тег `v1.0-tournament` — это не формальность, а способ прекратить споры. Если после турнира кто-то скажет «игра была другая», снимок под тегом покажет, какая именно.
- Жеребьёвку проводи при всех и один раз. Как только сетка опубликована, менять её нельзя — подозрение в подсуживании переживёт турнир.
- Репетицию не пропускай: матч до трёх побед может занять больше времени, чем кажется, и это лучше выяснить заранее.
- Если по итогам репетиции окажется, что матчи идут слишком долго, решение — сократить формат (до двух побед или до 60 секунд на раунд) — принимается **до** турнира и вписывается в правила и регламент.

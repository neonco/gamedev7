## Цель

- Сделать общую еду, за которой охотятся обе змейки.
- Считать очки каждого за раунд.
- Ускорить обе змейки одинаково.
- Вывести на экран очки и время.

## Артефакт

Еда одна и появляется только в свободной клетке. Съевший получает очко и растёт. На экране — очки обоих игроков и обратный отсчёт раунда.

## Разбор

### Еда не должна появляться ни в одной змейке

Раньше мы искали свободную клетку, не занятую одной змейкой. Теперь змеек две:

```python
def new_food(snakes):
    busy = []
    for snake in snakes:
        busy += snake.body
    free = []
    for x in range(COLS):
        for y in range(ROWS):
            if (x, y) not in busy:
                free.append((x, y))
    if not free:
        return None
    return random.choice(free)
```

`busy` — все занятые клетки обеих змеек. Обрати внимание: если еда окажется внутри любой из них, игра застрянет — обе будут ползать мимо несъедобного кружка.

### Одно очко — одному

Еда одна, поэтому съесть её может только одна змейка. Проверка происходит внутри `step`, и каждая змейка сравнивает свою голову с едой:

```python
ate = head == food
```

Если обе головы пришли в клетку с едой в один шаг — еду получают обе. Такой случай возможен только при лобовом столкновении, а там обе змейки погибают, поэтому до начисления дело не доходит. Проверь порядок строк у себя.

### Скорость общая

Соблазнительно ускорить каждую змейку по её очкам: кто больше съел, тот быстрее. Но тогда преимущество накапливается — съевший первым ускоряется и съедает ещё больше. Второй игрок уже не отыграется.

Поэтому ускоряем **обе змейки одинаково**, по общему числу съеденной еды:

```python
if step_snakes(snakes, food):
    food = new_food(snakes)
    tick = max(MIN_TICK, tick - TICK_STEP)
```

`step_snakes` возвращает `True`, если еду съел хоть кто-то. Одна еда — один шаг ускорения для обеих.

Это правило записано в документе [[pravila]]: «на каждую съеденную еду ускоряются обе змейки. Так честнее».

### Обратный отсчёт

Раунд ограничен по времени. Без ограничения осторожная пара может кружить по полю весь урок, а турнир требует, чтобы матч укладывался в расписание.

Время считаем от начала раунда:

```python
round_start = pygame.time.get_ticks()
...
left_ms = ROUND_TIME - (now - round_start)
```

Когда `left_ms` станет меньше нуля, раунд заканчивается, и победитель определяется по очкам.

### Очки на экране

Змейка сама знает, сколько съела, поэтому вывести счёт просто:

```python
def draw_hud(snakes, wins, round_number, left_ms):
    for index, snake in enumerate(snakes):
        name = font.render(
            f"{snake.name}: раунды {wins[index]} · еда {snake.eaten} · длина {len(snake)}",
            True, TEXT_COLOR,
        )
```

Здесь `wins` — победы в раундах, а `eaten` — еда за текущий раунд. Это разные числа, и путать их нельзя: можно съесть больше еды и всё равно проиграть раунд, врезавшись в стену.

Длина берётся через `len(snake)` — за это отвечает метод `__len__`, который мы добавили в [[15]]. Без него пришлось бы писать `len(snake.body)`.

## Код

Замени `new_food` на версию для двух змеек:

```python
def new_food(snakes):
    """Свободная клетка поля."""
    busy = []
    for snake in snakes:
        busy += snake.body
    free = []
    for x in range(COLS):
        for y in range(ROWS):
            if (x, y) not in busy:
                free.append((x, y))
    if not free:
        return None
    return random.choice(free)
```

Добавь настройки скорости и времени:

```python
TICK_STEP = 3             # на сколько ускоряемся за каждую съеденную еду
ROUND_TIME = 90_000       # миллисекунд на раунд
```


Вывод счёта на экран:

```python
def draw_hud(snakes, wins, round_number, left_ms):
    """Счёт по раундам, очки за раунд и оставшееся время."""
    line = f"Раунд {round_number}"
    text = font.render(line, True, TEXT_COLOR)
    screen.blit(text, (WIDTH // 2 - text.get_width() // 2, 8))

    seconds = left_ms // 1000
    timer = font.render(f"{seconds:02d}", True, TEXT_COLOR)
    screen.blit(timer, (WIDTH - 46, 8))

    for index, snake in enumerate(snakes):
        name = font.render(
            f"{snake.name}: раунды {wins[index]} · еда {snake.eaten} · длина {len(snake)}",
            True, TEXT_COLOR,
        )
        if index == 0:
            screen.blit(name, (12, HEIGHT - 30))
        else:
            screen.blit(name, (WIDTH - name.get_width() - 12, HEIGHT - 30))
```

Проверь:

- съешь еду первой змейкой и убедись, что обе ускорились, а очко получила только первая;
- дай времени дойти до нуля: раунд должен закончиться, и победит тот, у кого больше очков;
- проверь, что еда не появляется внутри змеек, даже когда они длинные.

## Шпаргалка

### Что должно работать

- Одна еда на поле, вне обеих змеек
- Съевший растёт и получает очко, второй — ничего
- Обе змейки ускоряются одинаково
- На экране очки обоих и таймер раунда

### Запомнить

- `busy` — занятые клетки **обеих** змеек: еда не должна появиться ни в одной.
- Ускоряются обе змейки по общему числу съеденной еды: иначе преимущество накапливается и второй игрок не отыграется.
- `eaten` — еда за раунд, `wins` — победы в раундах. Это разные числа.
- Время раунда считается от `round_start`, а не от запуска программы.

Спросите, почему нельзя ускорять только ту змейку, которая ест.

## Для учителя

- Общая скорость — хороший повод поговорить про баланс в играх: механика, которая кажется «справедливой по заслугам», легко превращается в снежный ком.
- Проверь, что `eaten` сбрасывается при новой расстановке: змейки создаются заново, поэтому сброс происходит сам собой. Если кто-то хранит счёт снаружи, он его не сбросит.
- Случай «обе головы на еде» разбери отдельно: он возможен только при лобовом столкновении, и там побеждает правило смерти, а не еды.

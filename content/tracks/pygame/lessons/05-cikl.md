## Цель

- Повторять действия, пока условие не выполнено.
- Освоить `while`, `while True` и `break`.
- Понять, зачем считать попытки и как это делается.
- Научиться не тащить в репозиторий лишние файлы.

## Артефакт

Программа `guess.py` работает до победы: после каждой попытки подсказывает, больше или меньше, а в конце сообщает, за сколько попыток игрок угадал.

## Разбор

### Пока

```python
while number != secret:
    ...
```

Читается: «пока число не равно загаданному — повторяй». Тело цикла повторяется, пока условие истинно. Как только оно стало ложным — цикл закончился и программа идёт дальше.

Это и есть решение проблемы прошлого урока: игрок получает столько попыток, сколько нужно.

### Бесконечный цикл с выходом

Есть второй, более удобный для игр способ:

```python
while True:
    ...
    if number == secret:
        print("Угадал!")
        break
```

`while True` означает «повторяй всегда». Выход делается командой `break` — она немедленно выкидывает из цикла.

> [!ошибка]
> Если `break` не сработает никогда, программа зависнет и будет крутиться бесконечно. Это не поломка компьютера — это ошибка в условии. Останавливается сочетанием клавиш, в терминале это обычно `Ctrl+C`.

### Счётчик

Чтобы считать попытки, нужна переменная, которая увеличивается на каждой итерации:

```python
tries = 0
...
    tries = tries + 1
```

Запись `tries = tries + 1` читается как «взять то, что лежит в коробке, прибавить один и положить обратно». Есть короткая форма: `tries += 1`. Она делает то же самое.

### Мусор в репозитории

Когда Python запускает программу, он создаёт служебную папку `__pycache__`. Это не твой код, это кэш, и в репозитории ему делать нечего: он будет меняться сам и мешать смотреть историю.

Для этого в корне репозитория лежит файл `.gitignore` — список того, что git должен игнорировать. Туда попадают служебные папки, временные файлы, сохранения редактора.

```gitignore
__pycache__/
*.pyc
.venv/
```

## Код

```python
import random

secret = random.randint(1, 100)
tries = 0

print("Я загадал число от 1 до 100. Попробуй угадать!")

while True:
    number = int(input("Твоя попытка: "))
    tries += 1

    if number > secret:
        print("Моё число меньше")
    elif number < secret:
        print("Моё число больше")
    else:
        print(f"Угадал! Тебе понадобилось попыток: {tries}")
        break
```

Проверь: угадай за минимальное число попыток. Подумай, какую стратегию ты использовал — скорее всего, делил диапазон пополам. Это самый быстрый способ, и он пригодится позже.

## Гит

Проверь, что мусор не попадает в снимок. Открой панель `Commit`: служебной папки `__pycache__` там быть не должно. Если она видна — `.gitignore` не сработал.

В PyCharm `.gitignore` можно не писать руками: правый клик по ненужной папке → `Git` → `Add to .gitignore`. PyCharm сам подставит строку.

Под капотом:

```bash
git pull
# ... работаем ...
git status
git add .
git commit -m "Довёл угадайку до конца и посчитал попытки"
git push
```

`git status` — это то же, что список в панели `Commit`: какие файлы изменены, какие новые, какие уже готовы к снимку. Если `__pycache__` всё же попал в репозиторий раньше, одной строки в `.gitignore` уже мало — файл придётся убрать из-под контроля отдельно, и это тема не сегодняшнего урока.

## Шпаргалка

### Что должно работать

- Игра идёт до победы, а не заканчивается после одной попытки
- В конце печатается число попыток
- Служебные файлы не попадают в репозиторий

### Запомнить

- `while True:` повторяет всегда, выход делает `break`.
- `tries += 1` — то же самое, что `tries = tries + 1`.
- Загаданное число от 1 до 100 угадывается **за 7 попыток**, если делить диапазон пополам.
- `.gitignore` — список того, что git не замечает.

### Если что-то не так

- Программа зависла — не сработал `break`. Останавливается `Ctrl+C`.
- В панели `Commit` видно `__pycache__` — проверь `.gitignore`.

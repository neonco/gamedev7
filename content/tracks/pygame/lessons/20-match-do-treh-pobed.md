## Цель

- Считать победы и завершать матч по правилу.
- Разобраться с ничьей: почему она не засчитывается никому.
- Сделать страховку от бесконечных переигровок.
- Начинать новый матч, не перезапуская программу.

## Артефакт

Матч идёт до трёх побед. Когда кто-то победил, игра объявляет итог и ждёт R. После R начинается новый матч с нулевым счётом.

## Разбор

### Три победы

Правило простое: кто первым набрал три победы в раундах, тот выиграл матч. Это число лежит в настройках:

```python
WIN_ROUNDS = 3
```

Проверка занимает одну строку:

```python
enough = max(wins) >= WIN_ROUNDS
```

`max(wins)` — большее из двух чисел. Если оно дотянуло до трёх, матч окончен.

### Ничья не приближает конец матча

Ничья — это когда погибли обе змейки с равным числом еды, или когда вышло время с равным счётом. По правилам ничья **не засчитывается никому**, и раунд переигрывается.

Это значит, что ничья не должна увеличивать счёт матча. Но её нужно посчитать, иначе пять ничьих подряд будут выглядеть как «ничего не произошло», и матч никогда не кончится.

```python
played = sum(wins) + (1 if winner is None else 0)
```

`played` — сколько раундов уже сыграно. Считается так: сколько-то раундов кто-то выиграл плюс этот, если он ничейный.

> [!важно]
> Зачем вообще считать ничьи, если они не засчитываются? Как страховку. Если пара будет играть на ничью, матч не должен длиться вечно.

### Страховка от бесконечного матча

```python
MAX_ROUNDS = 8
```

Если за восемь раундов три победы никто не набрал, матч решается по-другому: **по общему количеству съеденной еды за матч**. Для этого мы копим еду отдельно от раундового счёта:

```python
total_eaten[index] += snake.eaten
```

При полном равенстве и здесь — жребий. Это записано в правилах: [[pravila]].

Восемь — не случайное число: три победы плюс два поражения — это пять результативных раундов, и ещё три в запасе на ничьи.

### Кто выиграл матч

Отдельная функция, потому что случаев три:

```python
def match_winner(wins, total_eaten):
    """Победитель матча: 0, 1 или None, если решает жребий."""
    if wins[0] > wins[1]:
        return 0
    if wins[1] > wins[0]:
        return 1
    if total_eaten[0] > total_eaten[1]:
        return 0
    if total_eaten[1] > total_eaten[0]:
        return 1
    return None
```

`None` здесь означает «даже по еде поровну» — тогда в турнире бросят жребий.

### Новый матч без перезапуска

После матча игроки должны мочь сыграть ещё. Сбрасываем **всё состояние матча**:

```python
                elif state == "match_over" and event.key == pygame.K_r:
                    wins = [0, 0]
                    total_eaten = [0, 0]
                    round_number = 1
                    snakes, food = new_round()
                    tick = START_TICK
                    last_move = pygame.time.get_ticks()
                    round_start = last_move
                    state = "play"
```

Список длинный, и это ровно то, о чём мы говорили в [[13]]: сбрасывать надо всё, а не только видимую часть. Забудешь `total_eaten` — и в новом матче победитель определится по еде из прошлого.

## Шпаргалка

### Что должно работать

- Матч до трёх побед с объявлением победителя
- Ничья не засчитывается никому и раунд переигрывается
- R начинает новый матч с нуля

### Запомнить

- `max(wins) >= WIN_ROUNDS` — проверка победы в матче.
- Ничья **не приближает** конец матча, но считается: `played` нужен как страховка.
- После `MAX_ROUNDS` матч решается по общей съеденной еде, при полном равенстве — жребий.
- `total_eaten` копится по раундам и **обязательно сбрасывается** при новом матче.

### Проверьте вместе

Спросите, почему при новом матче нужно сбросить `total_eaten`, а не только счёт раундов.

## Для учителя

- Ничья — единственное место, где правило приходится объяснять через «зачем»: сама по себе она ничего не значит, но без счётчика ничей матч может не кончиться никогда.
- Домашка с убранным сбросом `total_eaten` — хорошая проверка понимания. Она ломает не сразу, а во втором матче, и это ровно тот класс ошибок, который стоит прочувствовать.
- Если кто-то спрашивает, почему победитель определяется по еде, а не по прожитым шагам: правило должно быть простым для объяснения вслух. «Кто больше съел» — понятно сразу.

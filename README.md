# Разработка игр, 7 класс — веб-приложение курса

Все уроки курса в одном статическом сайте: код, команды git, чек-листы, шпаргалки для печати, домашка и перекрёстные ссылки между уроками.

| Платформа | Репозиторий | Сайт |
|---|---|---|
| GitHub | [neonco/gamedev7](https://github.com/neonco/gamedev7) | [neonco.github.io/gamedev7](https://neonco.github.io/gamedev7/) |
| GitVerse | [neonco/gamedev7](https://gitverse.ru/neonco/gamedev7) | [neonco.gitverse.site/gamedev7](https://neonco.gitverse.site/gamedev7/) |

Пуш в GitHub — единственное, что нужно делать руками. Дальше всё автоматически: GitHub Pages собирает сайт из исходников, а workflow «Mirror to GitVerse» переносит ветки и теги в GitVerse.

Визуальный язык и паттерн сборки унаследованы от [`neonco/EGEINF`](https://github.com/neonco/EGEINF): Python-генератор, самодостаточный статический вывод, тёмная тема по умолчанию, никаких внешних зависимостей.

## Сборка

```bash
python3 build.py
```

Результат — в `docs/`. Никаких библиотек ставить не нужно, только Python 3.

Локальный просмотр:

```bash
cd docs && python3 -m http.server 8931
# открыть http://127.0.0.1:8931/
```

Открывать `docs/index.html` напрямую файлом можно, но тогда не подтянется `data/lessons.json` и не посчитается прогресс — браузеры запрещают `fetch` с `file://`.

## Как добавить урок

Создай файл в `content/tracks/pygame/lessons/`. Имя файла становится частью адреса, поэтому пиши его латиницей: `07-okno-i-cikl.md`.

Начало файла — короткий заголовок между `---`:

```
---
num: 7
title: Окно и игровой цикл
sprint: 2
time: 2 урока
artifact: Открывается окно, которое закрывается по крестику
git: [git pull, git commit -m, git push]
---
```

- `num` — номер урока, задаёт порядок и работает в перекрёстных ссылках.
- `title`, `artifact` — попадают на карту курса.
- `git` — команды, которые выводятся значками. Это карта того, что ученик освоил.
- `time`, `sprint` — организационное.

Дальше идёт текст с секциями `## `.

## Синтаксис

**Секции.** Названия фиксированы, каждая рендерится по-своему:

| Секция | Что внутри | Как выглядит |
|---|---|---|
| `## Цель` | список | стрелки |
| `## Артефакт` | список | выделенная рамка |
| `## Разбор` | текст, подзаголовки `###`, примеры | обычный текст |
| `## Код` | блоки ```python | с подсветкой и копированием |
| `## Гит` | блоки ```bash | команды с копированием |
| `## Чек-лист` | `- [ ]` | живые галочки, идут в прогресс |
| `## Шпаргалка` | подзаголовки `###` и списки | рамка с кнопкой «Распечатать» |
| `## Домашка` | нумерованный список | обычный текст |
| `## Связи` | ссылки `[[NN]]` или `[[block-1]]` | переходы между уроками и викторинами |
| `## Для учителя` | текст | скрыто под спойлером |

Любая другая секция выведется как обычный текст — можно добавлять свои.

**Шпаргалка** — то, что уходит на бумагу. Пишется по трём заголовкам: «Что должно работать», «Запомнить», «Проверьте вместе». Открытых полей для ответов в курсе нет: для отметок есть чек-лист, а печатать нужно короткую выжимку, а не анкету. Кнопка «Распечатать шпаргалку» печатает только её, без остальной страницы.

**Для учителя** рендерится как `<details>` — свёрнуто по умолчанию, чтобы методичка не попадалась ученику на глаза.

**Чек-лист:**

```
- [ ] пункт, который ученик отмечает
```

Галочки сохраняются в браузере и переносятся между ноутбуками кнопкой «Выгрузить прогресс» на карте курса.

**Врезки:**

```
> [!важно] не забыть про отступы
> [!ошибка] что будет, если...
> [!подсказка] как проще
```

**Перекрёстные ссылки:** `[[07]]`, `[[07|окно и цикл]]` или `[[block-1]]` для викторины. Генератор проверяет каждую ссылку и **падает с ошибкой**, если цель не существует. Битых ссылок в собранном сайте быть не может.

## Викторины

Лежат в `content/tracks/pygame/quizzes/`. Одна викторина на блок, минут на двадцать.

```
---
title: Викторина по блоку 1
block: 1
time: 20 минут
---

## Что делает команда `git commit`?

- [ ] отправляет файлы на сервер
- [x] сохраняет снимок файлов в историю

> `commit` — это снимок. На сервер отправляет `push`.
```

Каждый `## ` — отдельный вопрос. Варианты пишутся как чек-лист, где `- [x]` помечает верный ответ. Цитата после вариантов — это разбор, он показывается только после проверки.

На странице ученик отмечает варианты, жмёт «Проверить» и видит результат по каждому вопросу. Ответы хранятся в браузере, поэтому викторину можно закрыть и вернуться.

**Проверку можно подсмотреть:** правильный ответ лежит в разметке страницы, и технически его видно, если открыть исходный код. Это домашняя работа на совесть — для контроля пары вопросов стоит разобрать вслух на уроке. Проверка `check_site.py` следит, чтобы у каждого вопроса был ровно один верный вариант.

**Обозначения:** `` `код` ``, `**жирный**`, `[текст](https://ссылка)`.

## Рабочее окружение

Дети работают **только из PyCharm**. На первом уроке ставится четыре вещи: Python, PyCharm, `pygame-ce` и Git.

- PyCharm с версии 2025.1 — [один продукт](https://www.jetbrains.com/help/pycharm/unified-pycharm.html) вместо Community и Professional, ядро бесплатно. Отдельного ключа Professional не нужно, инструкция про его активацию устарела.
- `pygame-ce` требует **Python 3.10+**; готовые колёса есть под 3.10–3.15, так что подойдёт любая современная версия из установщика.
- В коде библиотека называется по-старому: `import pygame`. Писать `pygame_ce` не нужно.
- Библиотека ставится **в интерпретатор проекта**, а не в системный Python. Это главная причина ошибки `ModuleNotFoundError: No module named 'pygame'`.
- Git лежит в наборе вместе с остальными установщиками. Без него не работает ничего из блока про репозиторий: ни клонирование, ни коммиты. На машинах без прав администратора выручает PortableGit из того же выпуска Git for Windows.

Терминал в курсе нужен один раз — для скрипта `select-me`, который прописывает имя и почту автора коммитов. Всё остальное делается кнопками PyCharm: `Update Project`, `Commit`, `Push`, `Log`.

## Прогресс ученика

Прогресс — это отметки в чек-листах уроков и ответы в викторинах. Он лежит в `localStorage` браузера и никуда не отправляется, сервера у курса нет.

Чтобы перенести прогресс на другой ноутбук:

1. На карте курса нажать «Выгрузить прогресс» — скачается `progress-gamedev7.json`.
2. На другом ноутбуке открыть карту, нажать «Загрузить» и выбрать файл.

При желании файл можно положить в свой игровой репозиторий и возить с собой через git.

## Публикация

Сайт статический, и папка `docs/` в репозитории не хранится: её собирает CI перед публикацией. Так исходники и сайт не расходятся.

**GitHub.** Pages уже включён, источник — Actions. Workflow `.github/workflows/pages.yml` собирает сайт и выкладывает его. Перед сборкой запускается `tools/check_site.py`: если код в уроках разошёлся с разметкой или появилась битая ссылка, сайт не обновится.

**GitVerse.** Код синхронизируется автоматически: `.github/workflows/mirror-to-gitverse.yml` переносит ветки и теги при каждом пуше (нужен секрет `GITVERSE_TOKEN` в настройках репозитория — он уже установлен). Публикацией сайта занимается `.gitverse/workflows/pages.yml`.

> [!важно]
> На GitVerse публикацию нужно один раз включить руками: настройки репозитория → **Страницы** → включить и выбрать источник **Воркфлоу**. Без этого раннер не получает доступ к экшенам Pages, и workflow падает с `authentication required: Repository not found`. В API это поле (`has_pages`) только для чтения, поэтому автоматически не включается.
>
> Шаблоны («Simple HTML Page», «Jekyll») нажимать не нужно: они создают свой workflow и затрут наш. Адрес сайта — [neonco.gitverse.site/gamedev7](https://neonco.gitverse.site/gamedev7/).

> [!важно]
> Экшены Pages на GitVerse лежат в пространстве `actions/`, а не `gitverse/`, как написано в документации: `gitverse/upload-pages-artifact@v1.0.0` не существует, и job падает на разборе шагов с `repository not found`. Рабочий вариант — `actions/upload-pages-artifact@v1` и `actions/deploy-pages@v1`.

## Проверки

Три команды, которые стоит запускать после правок.

```
python3 tools/check_site.py      # пересоберёт сайт и сверит его с Markdown
python3 tools/check_snake.py     # проверит код змейки и листинги из уроков
node tools/check_ui.js           # проверит викторину и печать шпаргалки
```

**`check_site.py`** не требует ничего кроме Python. Он пересобирает сайт, сверяет **каждый блок кода** на странице с исходным Markdown, ищет неразрешённые перекрёстные ссылки, проверяет, что в уроках есть шпаргалка, что методичка спрятана под спойлер, что не осталось полей для открытых ответов и что в каждом вопросе викторины ровно один верный вариант. Эта проверка появилась не просто так: однажды регулярка подсветки съедала строки и комментарии внутри блоков кода, и все примеры на сайте показывали числа вместо текста. Глазами это замечается не сразу, а сверкой — мгновенно.

**`check_snake.py`** требует pygame (`python3 -m pip install pygame-ce`). Он проверяет логику эталонной змейки без окна — шаг, рост, стены, укус себя, заход на клетку уходящего хвоста, запрет разворота, WASD; прогоняет полный игровой цикл с поддельными часами и событиями; компилирует и запускает каждый полный листинг из уроков.

**`check_ui.js`** требует node и jsdom (`npm install jsdom`). Он открывает собранные страницы без браузера и делает то же, что ученик: отмечает варианты в викторине, жмёт «Проверить», смотрит счёт и разборы, сбрасывает и проверяет заново. Отдельно проверяет, что кнопка печати включает режим «только шпаргалка».

Если правишь код или задания, запусти все три — расхождение вылезет до урока, а не на уроке.
